## 一、设计题目

**校园课程资料智能检索与问答服务系统（EduRAG）**

本课题拟实现一款面向高校教学场景的课程资料智能检索与问答服务系统。系统以**检索增强生成（Retrieval-Augmented Generation, RAG）** 为核心算法，将分散存放于 QQ 群、学习通、教师个人主页的课件（PPT/PDF）、实验指导书、作业要求文档等教学资料集中管理，并通过**关键词检索 + 向量语义检索 + 大语言模型问答**三模式融合，为学生、教师、管理员提供"上传—审核—检索—问答—反馈"一体化服务。

系统采用前后端分离架构，后端以 **FastAPI + LangGraph + DeepSeek + ChromaDB** 构建多节点 RAG 编排管线，前端以 **React 19 + TypeScript + Ant Design 6** 构建三方角色门户。系统具备**三层提示注入防护**、**无答案拒答**、**答案引用标注**、**SSE 流式响应**、**联网兜底搜索**等前沿特性，能够在保证答案可追溯、可审计、安全可控的前提下，显著降低学生检索资料的时间成本，帮助教师发现教学盲区，辅助管理员实现资料合规治理。（摘要）

## 二、主要内容

`EduRAG` 系统按照"基础必做 + 前沿增强 + 课程补充"三层划分，共 **13 个核心功能模块**和 **3 项非功能性指标**。各模块在代码工程中分别对应 `backend/app/api/v1/` 下的路由、`backend/app/services/` 下的业务服务、`backend/app/graph/` 下的 RAG 编排节点，以及 `frontend/src/pages/` 下的三方门户页面，主要功能描述如下：

### 模块 1：用户认证与权限管理（F1）

- 支持学生 / 教师 / 管理员三种角色，账号统一使用**学号（学生）/ 工号（教师 / admin）**。
- 注册接口不暴露角色字段，学生注册默认 `student`；教师工号由管理员后台预设；admin 账号由初始化脚本创建。
- 基于 **JWT (HS256)** 双令牌机制（access 1h + refresh 7d）+ **bcrypt** 密码哈希，提供登录、注册、刷新令牌、修改密码、强制改密、角色鉴权等能力。
- 管理员可在后台执行**重置密码（生成临时密码 + force_password_change）/ 启用·禁用账号 / 角色升降级**等操作。
- 代码路径：`backend/app/api/v1/auth.py`、`backend/app/core/security.py`、`frontend/src/pages/auth/` 全套。

### 模块 2：课程资料上传与文档元数据管理（F2 / F3）

- 教师 / 管理员上传 **PDF / DOCX / TXT / PPTX / MD / 图片**，单文件最大 50MB；扩展名 + MIME 白名单校验；**SHA-256 哈希去重**。
- 上传时填写课程、文件类型（课件 / 实验指导书 / 作业要求 / 参考资料）、学期、标题、描述、标签（JSONB 数组）。
- 上传后自动入库 `documents` 表，处理状态机：`pending → processing → completed / failed`；审核状态机：`pending → approved / rejected`。
- 提供按课程 / 类型 / 状态筛选的分页列表、元数据编辑、软删除（级联清理 chunk 与向量）、admin 重新处理等操作。
- 代码路径：`backend/app/api/v1/documents.py`、`backend/app/services/document_processor.py`、`frontend/src/pages/teacher/DocumentUploadPage.tsx`、`DocumentListPage.tsx`。

### 模块 3：管理端审核与运营仪表盘（F7 / F13）

- 管理员端提供待审核文档列表、通过 / 驳回操作、驳回原因登记、**审核日志 (`audit_logs`)**完整留痕。
- **审核通过后才触发**异步文档解析—切分—向量化—入库管线（避免未审核内容浪费算力）。
- 仪表盘聚合展示：用户总数、文档总数 / 各状态分布、问答总数 / 拒答率、反馈统计、操作日志检索（按用户 / 操作类型 / 时间筛选）。
- 代码路径：`backend/app/api/v1/admin.py`、`frontend/src/pages/admin/ReviewList.tsx`、`UserManage.tsx`、`AuditLogPage.tsx`、`AdminHomePage.tsx`。

### 模块 4：RAG 检索 与 AI问答（F4 / F8 / F9 / F10 / F11）

这是项目的**核心算法与前沿增强模块**，全部以 **LangGraph StateGraph** 编排，包含 **10 个 Node + 4 个条件路由**，代码路径为 `backend/app/graph/`：

1. **文档解析与切分**：基于 **Docling** 主解析（PDF/DOCX/PPTX 表格保留）+ **PyMuPDF** 兜底，结合 **LangChain `RecursiveCharacterTextSplitter`**（`chunk_size=800`，`overlap=150`）切分。
2. **向量化**：双 Provider 抽象——优先调用 **SiliconFlow API（`BAAI/bge-m3`, 1024d）**，可降级至本地 `bge-large-zh-v1.5`。
3. **向量存储**：**ChromaDB PersistentClient**（`hnsw:space=cosine`），chunk metadata 含 `course_id`、`document_id` 等以支持按课程过滤。
4. **LangGraph 编排管线**（`backend/app/graph/builder.py`）：
   `classify_intent → rewrite_query → rag_search → rerank → [build_context | web_search | generate_answer] → review_output → [return_answer | reject]`
5. **意图分类（L1 防护）**：LLM 将输入分类为 `NORMAL / CHITCHAT / CHEATING / SENSITIVE / ATTACK`，非 NORMAL 直接拒答。
6. **多轮追问改写**：`rewrite_query` 节点基于近 3 轮上下文，将"可以再讲讲吗"等不完整问句改写为独立检索 query。
7. **混合检索 + Reranker**：向量召回 Top-20 → **SiliconFlow `bge-reranker-v2-m3`** 重排 → 取 Top-5；阈值不达拒答或走联网。
8. **联网兜底**：当内部资料相关性不足且用户开启 `use_web_search` 时，调用 **Tavily API** 搜索。
9. **答案生成（结构化输出）**：**DeepSeek v4-flash** 强制 `response_format=json_object`，输出 `{"answer": "..[来源1]..", "citations": [1,2]}`。
10. **输出审查（L3 防护）**：机械校验（虚假引用、空答案）+ 可选 LLM 语义审查。
11. **SSE 流式响应**：通过 `chain.astream()` + `StreamingResponse` 返回 `text/event-stream`。
12. **提示注入防护（L0+L1+L3）**：L0 正则过滤 → L1 意图分类 → L3 输出校验，覆盖简中 / 英文 / 文言文多语言一致拒答。
13. **无答案拒答**：相似度低于 `RAG_SIMILARITY_THRESHOLD=0.45` 时返回标准拒答提示，写入 `qa_history.is_rejected=TRUE`。

### 模块 5：问答历史与反馈记录（F5 / F6 / F12）

- 问答历史：`qa_history` 表 + **LangGraph AsyncPostgresSaver Checkpointer** 实现多轮对话会话持久化；提供按时间倒序、课程筛选的分页历史列表与详情回溯。
- 用户反馈：每条答案支持"有用 / 无用 / 错误"+ 可选文字说明；`feedback` 表 `UNIQUE(qa_id, user_id)` 保证一人一答案唯一反馈；支持修改 / 撤销。
- 教师数据洞察：按课程聚合**高频问题 Top-N**、**拒答问题清单（知识盲区）**，辅助教师备课。
- 代码路径：`backend/app/api/v1/qa.py`、`backend/app/api/v1/feedback.py`、`backend/app/graph/checkpointer.py`、`frontend/src/pages/student/QAHistory.tsx`、`QAPage.tsx`。

### 非功能性指标（N1 / N2 / N3）

| 指标 | 要求 | 实现要点 |
|------|------|----------|
| **N1 性能** | 关键词 < 1s / 语义 < 3s / 问答 < 5s / 并发 ≥ 20 | 异步 SQLAlchemy 2.0 + 双路并行 `asyncio.gather` + SSE 流式 |
| **N2 安全** | JWT + bcrypt + RBAC + 文件 / 注入 / XSS 防护 | 三层注入防护 + 文件白名单 + ORM 参数化 + react-markdown |
| **N3 移动端** | 基本浏览能力 | Ant Design 5 Grid 响应式断点 + 抽屉式导航 |

系统界面应满足以上功能要求，同时界面简洁美观、操作直观，符合"以搜索框为核心入口"的设计哲学。
